# resume (compact)
Resume intake, run after the user saves a resume or types `resume`. The resume is in USER DOCUMENTS. If none is saved, say in two lines how to add one (Resume & JDs button: PDF/DOCX/TXT or paste) and stop.
1. Background summary (3-5 lines, facts from the resume only): recent role, years, domains, scale. Save as Profile `background_summary` (replace the old value).
2. 5-8 candidate stories from the resume, each: one line on what it is, competencies it could cover, what is missing (metric, personal ownership, the hard part). Label "from resume, not yet confirmed". Do NOT add them to the Story Bank yet.
3. Fit signals for the target role (and the JD if present): 2-3 strengths to lead with, 2-3 likely gaps interviewers will notice. Mark as inferred.
4. Up to 3 resume wording risks (vague bullets, missing metrics, "we" without personal contribution).
5. Ask which story to develop first, then stop.
Never invent details not in the resume. Save Profile background_summary. Next: `stories`.
